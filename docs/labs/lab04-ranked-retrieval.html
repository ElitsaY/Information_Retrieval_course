Lab 04

Ranked Retrieval: TF-IDF, Cosine Similarity and BM25

TF-IDF Cosine similarity BM25 Cranfield

Overview of the lab

So far our retrieval systems answered a binary question: does this document match the query? Real search systems need to answer a harder one: which matching documents should appear first? In this lab we move from Boolean retrieval to ranked retrieval: represent documents and queries with weighted terms, score their similarity, and return an ordered list. We start with a tiny corpus where every number can be checked by hand, then move to a real IR benchmark.

  1. From matching to ranking: a score per document.
  2. A tiny corpus: term frequency and document frequency by hand.
  3. Inverse document frequency: rare terms matter more.
  4. TF-IDF: one weighted vector per document.
  5. Cosine similarity: rank by the angle between query and document.
  6. Real IR data: Cranfield: documents, queries and relevance judgments.
  7. TF-IDF with scikit-learn and search with cosine similarity.
  8. BM25: term-frequency saturation and length normalization.
  9. TF-IDF vs BM25 and three experiments.
  10. Saving runs for Lab 05, concept check, optional extension.
  • Estimated time: 2.5–3 hours. Prerequisites: inverted indexes, document and term frequency, text preprocessing, basic NumPy/Python.

From matching to ranking

Take the query retrieval relevant documents, and suppose three documents contain at least one query term. A Boolean system can tell us that they match, but not which one is best. A ranked retrieval system computes a score for each document

\[ \operatorname{score}(q, d) \]

and returns the documents in descending order of score, \(d_{(1)}, d_{(2)}, \ldots, d_{(k)}\). The score is not a probability of truth; it is a numerical signal used to order documents.

Three closely related ideas:

  1. TF-IDF: a term gets more weight when it is frequent in the document but rare in the collection.
  2. Cosine similarity: compare the query vector with document vectors while controlling for vector length.
  3. BM25: a classical probabilistic ranking function that adds term-frequency saturation and document-length normalization.

Rarity

Inverse document frequency

📐 Inverse document frequency

With \(N\) the number of documents and \(df_t\) the number of documents containing \(t\):

\[ idf(t) = \log \frac{N}{df_t} \]

A rare term gets a larger IDF. A term in every document gets \(idf(t) = \log 1 = 0\).

The IR intuition behind it: a term is useful for retrieval when it helps distinguish some documents from others.

4Why is relevant more informative than documents for this query?

relevant occurs in 1 document, so \(idf = \ln 5 \approx 1.609\); documents occurs in 4, so \(idf = \ln(5/4) \approx 0.223\). Matching documents tells us almost nothing, since nearly every document matches it; matching relevant singles out D1.

A practical detail: there is more than one TF-IDF formula

  • Textbook: \(idf(t) = \log \frac{N}{df_t}\).
  • scikit-learn's default TfidfVectorizer (smooth_idf=True): \(idf(t) = \ln \frac{1 + N}{1 + df_t} + 1\). The +1 inside acts as if one extra document contained every term; the +1 outside keeps terms that occur everywhere from being ignored completely.
  • So the exact scores differ between implementations even when the ranking idea is the same. ❗ Do not compare raw scores from two systems before checking which weighting formula they use.
idf.py (a solution) Python ▾ 
import math

def idf(N, df):
    return math.log(N / df)

for term, df_t in [("retrieval", 2), ("relevant", 1), ("documents", 4)]:
    print(term, round(idf(5, df_t), 4))
# retrieval 0.9163
# relevant 1.6094
# documents 0.2231
Weighting

TF-IDF

📐 TF-IDF weight
\[ tfidf(t, d) = tf(t, d) \times idf(t) \]

A balance: a high \(tf\) means the term matters inside this document; a high \(idf\) means the term is discriminative across the collection.

Raw term frequency is only one option. A common transformation dampens the effect of repeated terms:

\[ tf'(t,d) = \begin{cases} 1 + \log tf(t,d), & tf(t,d) > 0 \\ 0, & \text{otherwise} \end{cases} \]

tfidf_vectors.py (a solution) Python ▾ 
from collections import Counter
import math
import numpy as np

toy_docs = {
    "D1": "information retrieval finds relevant documents",
    "D2": "boolean retrieval returns matching documents",
    "D3": "tf idf weights rare terms in documents",
    "D4": "bm25 uses term frequency and document length",
    "D5": "search engines rank documents for user queries",
}
query = "retrieval relevant documents"

def tokenize(text):
    return text.lower().split()

tokenized_docs = {doc_id: tokenize(text) for doc_id, text in toy_docs.items()}
vocabulary = sorted({token for tokens in tokenized_docs.values() for token in tokens})
N = len(tokenized_docs)

df = Counter()
for tokens in tokenized_docs.values():
    for token in set(tokens):
        df[token] += 1

idf_values = {term: math.log(N / df[term]) for term in vocabulary}

def tfidf_vector(tokens):
    counts = Counter(tokens)                      # words outside the vocabulary are ignored
    return np.array([counts[term] * idf_values[term] for term in vocabulary])

document_vectors = {doc_id: tfidf_vector(tokens) for doc_id, tokens in tokenized_docs.items()}
query_vector = tfidf_vector(tokenize(query))       # the collection's idf, not the query's

print(len(vocabulary))                             # 27
print(np.round(query_vector[query_vector > 0], 4)) # [0.2231 1.6094 0.9163]  (documents, relevant, retrieval)
Vector space

Vector-space retrieval and cosine similarity

Once queries and documents are vectors, we need a similarity function. The dot product \(q \cdot d = \sum_i q_i d_i\) is a start, but longer vectors can have larger dot products simply because they contain more weighted terms.

📐 Cosine similarity
\[ \cos(q, d) = \frac{q \cdot d}{\|q\| \, \|d\|} \]

It normalizes by the vector lengths. For non-negative TF-IDF vectors it lies between 0 and 1; a score near 1 means the vectors point in similar directions.

cosine.py (a solution) Python ▾ 
def cosine_similarity_manual(a, b):
    norm_a, norm_b = np.linalg.norm(a), np.linalg.norm(b)
    if norm_a == 0 or norm_b == 0:        # a zero vector has no direction
        return 0.0
    return float(np.dot(a, b) / (norm_a * norm_b))

ranking = sorted(
    ((doc_id, cosine_similarity_manual(query_vector, vector)) for doc_id, vector in document_vectors.items()),
    key=lambda pair: pair[1],
    reverse=True,
)
for doc_id, score in ranking:
    print(doc_id, round(score, 4))
# D1 0.6339
# D2 0.162
# D3 0.0068
# D5 0.0068
# D4 0.0
5Which document ranks first, and why?

D1 (0.634). It is the only document with all three query terms, including the rarest one, relevant, which has the largest weight in the query vector. D2 is second (0.162): it shares retrieval and documents.

6Is a document with more query-term matches guaranteed to have the highest cosine similarity?

No. Matches are weighted by IDF, so one rare term can outweigh several common ones, and the score is divided by the document's length: a long document with many other heavy terms points in a different direction. D3 and D5 each match one term but score only 0.007, because documents has a tiny IDF and both documents are longer.

7What happens if the query contains only words unseen in the collection?

Its vector is all zeros (unseen words are not in the vocabulary), so \(\|q\| = 0\). The formula would divide by zero; with the zero-vector check every document scores 0 and the ranking is meaningless. Try zzz in the widget.

Search

Search with cosine similarity

TfidfVectorizer(norm="l2") L2-normalizes the document vectors, and vectorizer.transform([query]) normalizes the query the same way. For unit vectors the cosine is just the dot product, \(\cos(q, d) = q^\top d\), so one sparse matrix product scores every document.

search_tfidf.py (a solution) Python ▾ 
import numpy as np

def search_tfidf(query, k=10):
    q = vectorizer.transform([query])
    scores = (X @ q.T).toarray().ravel()           # cosine: both sides are L2-normalized
    top_indices = np.argsort(-scores, kind="stable")[:k]

    results = []
    for rank, i in enumerate(top_indices, start=1):
        results.append({
            "rank": rank,
            "doc_id": doc_ids[i],
            "score": float(scores[i]),
            "title": titles[i],
        })
    return results

for q in queries[:5]:
    print(q.query_id, q.text)

Probabilistic

BM25

Why TF-IDF is not the end of the story

TF-IDF gives two important ingredients: terms repeated in a document can matter more, and rare terms can matter more than common ones. But raw TF has problems.

  • Repetition: if a term occurs once in document A, twice in B and twenty times in C, should C get twenty times the contribution of A? Usually not: after a few occurrences, seeing the term again gives diminishing evidence. This motivates term-frequency saturation.
  • Length: a term occurring 4 times in a 40-word document means something different from 4 times in a 4,000-word document.

Both ideas are built into BM25.

📐 BM25
\[ \operatorname{BM25}(q, d) = \sum_{t \in q} idf(t) \, \frac{tf(t,d)\,(k_1 + 1)}{tf(t,d) + k_1 \left(1 - b + b \, \frac{|d|}{\operatorname{avgdl}}\right)} \qquad idf(t) = \ln\left(1 + \frac{N - df_t + 0.5}{df_t + 0.5}\right) \]

\(tf(t,d)\): term frequency in \(d\); \(df_t\): documents containing \(t\); \(N\): collection size; \(|d|\): document length; \(\operatorname{avgdl}\): average document length; \(k_1\): term-frequency saturation; \(b\): document-length normalization. Typical starting values: \(k_1 = 1.2\), \(b = 0.75\). These are not universal constants.

  • \(k_1\), saturation: with a small \(k_1\) additional occurrences saturate quickly; with a larger \(k_1\) repeated occurrences keep increasing the score for longer. The contribution of one term never exceeds \(idf(t)\,(k_1 + 1)\).
  • \(b\), length normalization: \(b = 0\) ignores document length; \(b = 1\) applies full normalization; around 0.75 is a common starting point.

Build BM25 from scratch (Exercise 8)

Reuse an inverted-index style representation from the earlier labs: tokenize with \b\w+\b, then build the document lengths, the average length, the document frequencies, and postings of (doc_index, term_frequency). For short keyword queries, each unique query term contributes once.

bm25.py (a solution) Python ▾ 
import math
import re
from collections import Counter, defaultdict
import numpy as np

TOKEN_RE = re.compile(r"\b\w+\b", flags=re.UNICODE)

def bm25_tokenize(text):
    return TOKEN_RE.findall(text.lower())

tokenized_docs = [bm25_tokenize(text) for text in texts]
N = len(tokenized_docs)
doc_lengths = np.array([len(doc) for doc in tokenized_docs])
avgdl = doc_lengths.mean()

postings = defaultdict(list)
for doc_index, tokens in enumerate(tokenized_docs):
    for term, tf in Counter(tokens).items():
        postings[term].append((doc_index, tf))
df = {term: len(term_postings) for term, term_postings in postings.items()}

def bm25_idf(term):
    return math.log(1 + (N - df[term] + 0.5) / (df[term] + 0.5))

def search_bm25(query, k=10, k1=1.2, b=0.75):
    scores = np.zeros(N, dtype=float)
    query_terms = set(bm25_tokenize(query))      # each unique query term contributes once
    for term in query_terms:
        if term not in postings:
            continue
        term_idf = bm25_idf(term)
        for doc_index, tf in postings[term]:
            denominator = tf + k1 * (1 - b + b * doc_lengths[doc_index] / avgdl)
            contribution = term_idf * tf * (k1 + 1) / denominator
            scores[doc_index] += contribution
    top_indices = np.argsort(-scores, kind="stable")[:k]
    return [{"rank": rank, "doc_id": doc_ids[i], "score": float(scores[i]), "title": titles[i]}
            for rank, i in enumerate(top_indices, start=1)]

# sanity checks
assert avgdl > 0
assert len(doc_lengths) == len(docs)
assert all(length >= 0 for length in doc_lengths)
assert all(r["score"] == 0 for r in search_bm25("zzzzzzzzzzzzzz"))

Document-length normalization

11What happens when \(b = 0\)? Which documents are penalized as \(b\) increases? Why might aggressive length normalization sometimes hurt?

With \(b = 0\) the length factor is 1 for every document, so the same \(tf\) gives the same contribution in a 30-word and a 300-word abstract. As \(b\) grows, documents longer than average are penalized (their denominator grows) and shorter ones are boosted. Aggressive normalization hurts when long documents are long because they have more relevant content (a thorough report on the topic), not because they ramble: it then pushes the best documents down in favour of short ones that merely mention the term.

C1Why not rank documents using raw term frequency only?
Frequent words that carry no meaning (the, of) would dominate, every query term would count the same however common it is, and long documents would win simply by containing more words.

      
C2What does IDF measure?
How rare a term is in the collection: the log of the inverse of the fraction of documents containing it. Rare terms get high IDF, common terms low IDF.

      
C3Why does a term appearing in every document carry little retrieval information?
Knowing that a document contains it does not separate that document from any other; with \(\log(N/df)\) its IDF is exactly 0.

      
C4What problem does cosine normalization address?
Vector length: without it, long documents with many weighted terms get large dot products just for being long. The cosine compares directions, not magnitudes.

      
C5Why are TF-IDF scores from two libraries not necessarily numerically identical?
They use different variants: raw vs log TF, \(\log(N/df)\) vs scikit-learn's smoothed \(\ln\frac{1+N}{1+df} + 1\), different normalization and tokenization. Rankings may agree while raw scores differ.

      
C6What is TF saturation?
Each additional occurrence of a term adds less to the score than the previous one, and the contribution approaches a ceiling (\(idf \cdot (k_1 + 1)\) in BM25) instead of growing linearly.

      
C7What problem does BM25's \(b\) parameter address?
Document length: a long document contains more occurrences of any term by chance. \(b\) controls how much a document's term frequencies are discounted relative to the average length.

      
C8What happens when \(b = 0\)?
Length normalization is switched off: the same \(tf\) contributes the same amount in every document, whatever its length.

      
C9Can a document have a high BM25 score even if it does not contain every query term?
Yes. BM25 sums independent per-term contributions, so a document with several occurrences of the rarest query terms can outscore one that contains every term once. There is no AND requirement.

      
C10Why can we not determine the better ranker by inspecting only a few search results?
A few results for a few queries are a small, biased sample; judgments can be incomplete and subjective, and differences on some queries can reverse on others. We need relevance judgments over all queries and a metric: Lab 05.

Summary: key takeaways

    
documents → preprocessing → term statistics (tf, df, idf) → scoring: TF-IDF + cosine, or BM25 → ranked list

    
    
      
  1. Ranking: a score per document orders the results; it is a signal, not a probability of relevance.
    2. 
      
  2. tf, df, idf: \(tf\) is local to a document, \(df\) and \(idf = \log(N/df)\) are collection statistics; compute the query's weights with the collection's IDF.
    3. 
      
  3. TF-IDF + cosine: weight terms by \(tf \times idf\) and compare directions, so long documents are not favoured for their length.
    4. 
      
  4. BM25: saturating TF (\(k_1\)) and length normalization (\(b\)); defaults \(k_1 = 1.2, b = 0.75\) are a start, not constants.
    5. 
      
  5. Variants: different libraries use different formulas; never compare raw scores across them.
    6. 
      
  6. Next: the question is no longer "can we retrieve documents?" but "how do we know whether the ranking is good?", the subject of Lab 05.
