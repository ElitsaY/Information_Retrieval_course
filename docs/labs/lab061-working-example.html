Lab 06.1

Working Example: Scraping a News Article

Page anatomy Images Text Predict, then run
Work in progress These notes are still being written and reviewed: content may change, and some parts may still contain mistakes.

This page goes with lab06/petel_article.py, which scrapes the title, date, text and main image of one news article on petel.bg. A web page holds much more than the article: navigation, ads, share buttons and text that is the same on every article. Scraping is mostly about leaving things out. All numbers below come from the page as it was on 23 November 2026.

Page anatomy

What is on the page

A sketch of the article page (not to scale). The browser shows all of it, and requests downloads all of it. Switch to What the script keeps, then click any block to see what it is and how to find it.

The code

Scraping the article in five parts

The code is lab06/petel_article.py, split into five parts. Parts 1 and 2 are below, part 3 is with the text, and parts 4 and 5 are with the images. Run the parts one after another, for example in a notebook. Under each line is what it returns. The steps are the same as for the job ad in Lab 06, Part V.

1. Download the page and find the article

requests downloads the HTML and BeautifulSoup parses it. Everything we want is inside <article class="preview">, so from here on we search only inside article.

step 1 · download and parse Python ▾ 
import os
from urllib.parse import urljoin

import requests
from bs4 import BeautifulSoup

URL = "https://petel.bg/Silna-gramotevichna-burya-vrahlita-Varna__679431"
HEADERS = {"User-Agent": "IRCourseBot/0.1 (student lab crawler)"}

soup = BeautifulSoup(requests.get(URL, headers=HEADERS, timeout=10).text, "html.parser")
article = soup.select_one("article.preview")        # the block with the article

2. The title and the date

The title is the only <h1> in the article. The date div also holds the comment count in a <span>, so we take only the text that belongs to the div itself.

step 2 · title and date Python ▾ 
title = article.find("h1").get_text(strip=True)
title
# 'Силна гръмотевична буря връхлита Варна'

# the date div also holds the comment count in a <span>: take only its own text
date = article.select_one("div.item-date").find(string=True, recursive=False).strip()
date
# '23.11.2026 / 14:31'
Text

330 of 535 words are the article

The visible text of the whole page (scripts excluded) has 535 words. div.item-text has 403 of them, but its last 73 are the same on every article: the advertising price, "Последните новини виж – ТУК!", and the fact-checking and photo e-mails. The script stops at the editor's line, "Редактор …", and keeps 330.

💡 The e-mails come out as [email protected], not as addresses. The site hides them in the HTML, and a script in the browser decodes them (Cloudflare e-mail protection). This is dynamic content on a "static" page: what requests gets is not always what the browser shows.

Why it matters for IR: the boilerplate is identical in every article. Index 1,000 articles with it, and a query about "реклама" matches all of them.

3. The code: collect the paragraphs

The text is in the <p> tags of div.item-text. We stop at the paragraph that starts with "Редактор", because everything after it is the same on every article. We also skip empty paragraphs.

step 3 · text Python ▾ 
paragraphs = []
for p in article.select_one("div.item-text").find_all("p"):
    line = p.get_text(" ", strip=True)
    if line.startswith("Редактор"):                  # the end of the article
        break
    if line:                                         # skip empty paragraphs
        paragraphs.append(line)
text = "\n\n".join(paragraphs)

len(paragraphs), len(text.split())
# (14, 330)
paragraphs[0]
# 'Кадър Метео Балканс'   (the photo credit)
Images

Only 1 of the 14 images is the article's photo

soup.find_all("img") finds 14 images on the page. Hover over a tile to see where the image comes from.

kept by the script   left out

  • Ads: 9 images come from the site's ad server (ad.petel.bg/www/delivery/avw.php?zoneid=…). The HTML has only links to the server, not the image files. In a search engine's collection, ads are noise. And if you download them, the ad server may count it as a view of the ad.
  • The promo banner is inside the article text. It advertises the site itself ("Добави Petel.bg в Google") and is hosted on another site. So an image can be inside the right container and still not be part of the article.
  • ❗ The photo is inside a div with the class etargetnet_ads. If you drop every element with "ads" in its class, you lose the article's photo. All 9 ads stay, because their containers have other class names.

Two copies of the photo

The page also names its main image in a <meta property="og:image"> tag. Social networks use this tag for link previews. It often changes less than CSS class names do, but here it points to a smaller copy of the photo.

4. The code: find the photo and download it

The HTML does not contain the image. It contains only the image's address. So getting the image takes two steps: find the address in the HTML, then download the file from that address with a second request.

In the HTML<img class="img-responsive" src="https://static.petel.bg/…/big_Screenshot_…png">
↓ img["src"] reads the address (a str)
The address"https://static.petel.bg/…/big_Screenshot_…png"
↓ requests.get(image_url) is a second request: it downloads the file itself
The fileimage.content → b'\x89PNG\r\n…' (bytes, 531,684 of them)
↓ open(image_file, "wb").write(image.content) (part 5)
On your diskarticle_679431/image.png
step 4 · image Python ▾ 
# the photo; the first <img> in the article is the Facebook button
img = article.select_one("img.img-responsive")
# urljoin makes relative paths such as img/logo.png absolute
image_url = urljoin(URL, img["src"])
image_url
# 'https://static.petel.bg/resources/2026/11/23/big_Screenshot_-_2026-11-23T143039.281.png'

# a second request, for the image itself
image = requests.get(image_url, headers=HEADERS, timeout=10)
image.headers["Content-Type"], len(image.content)
# ('image/png', 531684)
  • article.select_one("img.img-responsive") finds the <img> tag of the photo, not the Facebook button's. It is only a piece of HTML, not a picture.
  • img["src"] reads the tag's src attribute: the address, as a string.
  • urljoin(URL, img["src"]) turns the address into a full URL. Here it is already full, so nothing changes. A relative path such as img/logo.png would become https://petel.bg/img/logo.png.
  • requests.get(image_url) is the second download. The first one got the page; this one gets the picture.
  • image.content is the downloaded file as bytes. We use .content, not .text, because a PNG is not text.
  • ❗ Finding the <img> is not the same as having the image. You have a tag that points to the image, like a link you still have to click.
?Check: what would img["src"] return if the site wrote src="/resources/photo.png", and what would urljoin(URL, img["src"]) turn it into?

img["src"] returns the string exactly as written, '/resources/photo.png'. urljoin adds the site from URL: 'https://petel.bg/resources/photo.png'. Without it, requests.get would fail, because a path alone is not a URL.

The code

5. Save the text and the image

Both go into a folder named after the article's id. Text is written with "w" and an encoding. The image is written with "wb", because it is bytes, not text.

step 5 · save Python ▾ 
OUT_DIR = "article_" + URL.rsplit("__", 1)[-1]      # article_679431
os.makedirs(OUT_DIR, exist_ok=True)

with open(os.path.join(OUT_DIR, "article.txt"), "w", encoding="utf-8") as f:
    f.write(f"{title}\n{date}\n{URL}\n\n{text}\n")

# keep the extension of the image (.png)
image_file = os.path.join(OUT_DIR, "image" + os.path.splitext(image_url)[1])
with open(image_file, "wb") as f:      # "wb": an image is bytes, not text
    f.write(image.content)

sorted(os.listdir(OUT_DIR))
# ['article.txt', 'image.png']
  • os.path.splitext(image_url)[1] takes the extension from the URL, '.png', so the file is saved as image.png.
  • open(image_file, "wb") opens the file for writing bytes. Text mode ("w") would fail, because image.content is bytes, not a string.

Guess what each line returns before you open it. soup is the whole page and article = soup.select_one("article.preview").

'img/logo.png': the site's logo, and a relative URL. The first image in the HTML is not the most important one.

One image, hosted on vihrogon.bg: the "Добави Petel.bg в Google" banner, not a photo of the storm.

403 words, of which 73 are boilerplate. The script keeps 330.

6soup.find("meta", property="og:image")["content"]

The medium_…png copy, 702 × 371 pixels. The article shows the big_…png copy, 933 × 493.

7Drop every element whose class contains "ads" (soup.select('[class*=ads]')), then look for the photo and the ads.

The filter removes 6 elements: 5 div.ads-caption and div.etargetnet_ads, the photo's container. The photo is gone, and all 9 ad images are still there.

Takeaway

  • A page is content + navigation + ads + boilerplate. Find the container first, then the fields inside it.
  • Don't trust order or names. The first image is the logo, and the photo's container is called …_ads. Check every selector on the real page.
  • Boilerplate repeats on every page. Leave it out, or every document in your index matches the same words.
